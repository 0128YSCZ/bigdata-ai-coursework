Agent（智能体）

人工智能核心概念 生成日期：2026-09-05

1. 一句话定义

Agent 是一种能够感知环境、自主决策并执行动作以实现特定目标的实体。

个人理解

Agent 不只是“回答问题”的模型，而是一个有目标、有记忆、能行动的“小助手”。它可以调用工具、分步骤完成任务，并在过程中根据反馈不断调整。例如，让 Agent 帮我订机票，它不只是给建议，而是会查航班、比价、填写订单，最后返回结果。

2. 核心机制与组成

  • 感知（Perception）：从环境或用户输入中获取信息，如读取文件、调用 API、接收用户指令。
  • 推理/规划（Reasoning & Planning）：把大目标拆成可执行的小步骤，决定先做什么、后做什么。
  • 记忆（Memory）：保存短期上下文和长期知识，使 Agent 能跨会话保持连贯。
  • 工具调用（Tool Use）：在需要时调用外部工具（搜索引擎、计算器、数据库、代码执行器等）。
  • 行动/执行（Action）：把规划结果转化为实际输出或操作，并反馈给环境。
关键循环：感知 → 规划 → 行动 → 观察结果 → 再规划 → 再行动，直到目标达成或遇到终止条件。

3. 具体应用场景

场景：课程论文资料整理助手。

我向 Agent 提出需求：“帮我找三篇关于 Transformer 在大数据场景下应用的论文，并整理成表格。”Agent 会：

  1. 调用搜索引擎检索相关论文；
  2. 读取论文摘要，提取作者、年份、核心方法；
  3. 生成 Markdown/Excel 表格，列出论文名称、方法、实验数据集、结论；
  4. 如果我要求“只保留 2023 年后的”，它会基于记忆再次过滤。

这个场景体现了 Agent 不只是“生成文本”，而是能主动调用工具、迭代完成多步骤任务。

4. 易混淆问题与使用边界

  • Agent ≠ 大模型：大模型是 Agent 的“大脑”，Agent 还包括记忆、工具、目标管理、执行循环等组件。
  • Agent ≠ 传统程序：传统程序按固定逻辑执行，Agent 能在开放环境中根据反馈动态调整策略。
  • 边界：Agent 的能力受限于工具质量、权限安全和上下文长度；不能假设它一定能自主完成复杂任务，关键决策仍需人工审核。
注意：不要误以为 Agent 是“全知全能”的。它可能产生幻觉、调用错误工具或在长任务中丢失目标，因此需要人在环路（Human-in-the-loop）监督。
